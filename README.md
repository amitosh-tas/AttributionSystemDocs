# Elysium Attribution SDK documentation

A single-page developer documentation site built with React, TypeScript, Vite, and Tailwind CSS v4. Syntax highlighting uses highlight.js (core build with only bash, JavaScript, and XML).

## Run

```bash
npm install
npm run dev        # local dev server
npm run typecheck  # tsc --noEmit
npm run build      # typecheck + production build into dist/
```

## Structure

| Path | Purpose |
|---|---|
| `src/docs/DocsPage.tsx` | All page content |
| `src/docs/sections.ts` | Navigation source of truth (sidebar, table of contents, scroll-spy) |
| `src/docs/snippets.ts` | Code samples, kept verbatim from the integration flow, plus the direct-API samples for non-npm sites (`/v1/touches`, `/v1/identify`, `/v1/checkout-sessions`) |
| `src/docs/meta.ts` | SDK name, package name, and the **version badge placeholder** |
| `src/components/` | `CodeBlock` (highlighting + copy), `Callout`, `DocTable`, `DocSection`, `Header`, `Sidebar`, `TableOfContents` |

## Before launch

- Set `VERSION_LABEL` in `src/docs/meta.ts` (currently `vX.Y.Z`).
- Replace everything marked **Needs confirmation** once verified against the SDK source / the template generated by `npx elysium init`:
  - configuration option names (`Configuration reference` shows a placeholder only),
  - where the CLI writes `elysium.config.js`,
  - the unit expected by `data-amount` (do not assume rupees vs paise),
  - the list of supported `data-gateway` identifiers,
  - for the non-npm section: required request fields, error status codes, and how the checkout token reaches the order on Shopify/WordPress.
- When adding a section, add it to `sections.ts` and give the element in `DocsPage.tsx` the same `id`.
